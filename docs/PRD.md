## 2. 产品概述

- **2.1 产品名称与定位**
  - **产品名称**: 竖式计算练习页生成器
  - **产品定位**: 一款面向学生和教师的在线工具，用于自动生成包含竖式计算题目的练习页面，支持打印输出，旨在提高学习效率和作业批改便利性。
- **2.2 产品愿景与使命**
  - **愿景**: 成为学生数学练习和教师作业布置的首选工具，让竖式计算练习变得更高效、更规范。
  - **使命**: 通过技术手段，将重复性的题目生成和排版工作自动化，解放教师和家长的时间，同时为学生提供清晰、标准的练习材料。
- **2.3 价值主张与独特卖点(USP)**
  - **价值主张**: 快速、轻松地生成专业、可打印的竖式计算练习题。
  - **独特卖点**:
    - **自动排版**: 自动将题目以4x5的网格布局排版在A4页面上。
    - **数据驱动**: 直接从指定的JSON文件读取题目，易于更新和扩展。
    - **打印优化**: 生成的页面专为A4打印优化，格式清晰，节省纸张。
- **2.4 目标平台列表**
  - **Web**: 核心平台，用于展示题目、生成页面并提供打印功能。
- **2.5 产品核心假设**
  - 用户（教师/家长）需要一种比手动出题、排版更高效的方式来创建竖式计算练习。
  - 学生需要格式清晰、统一的练习题来进行计算训练。
  - 用户具备基本的网页浏览和打印操作能力。
- **2.6 商业模式概述**
  - 初期为免费工具，旨在解决核心用户痛点。未来可考虑通过增值功能（如错题本、在线答题、智能分析等）探索商业化。

## 3. 用户研究

- **3.1 目标用户画像**
  - **3.1.1 人口统计特征**
    - **画像一：小学数学教师 (王老师)**
      - 年龄: 30-50岁
      - 职业: 小学中低年级数学教师
      - 技术熟练度: 中等，熟悉常用办公软件和网络应用。
    - **画像二：小学生家长 (李女士)**
      - 年龄: 30-45岁
      - 职业: 不限
      - 技术熟练度: 高，频繁使用各类在线应用。
  - **3.1.2 行为习惯与偏好**
    - **王老师**: 经常需要为学生布置家庭作业，倾向于使用能节省备课时间的工具。注重练习题的规范性和覆盖面。
    - **李女士**: 关注孩子的学习进度，希望有便捷的工具辅导孩子练习，偏好界面简洁、操作直接的应用。
  - **3.1.3 核心需求与痛点**
    - **王老师**:
      - **痛点**: 手动出题、用Word排版打印格式费时费力，难以保证每次格式都统一美观。
      - **需求**: 快速生成符合教学要求的、格式整齐的练习卷。
    - **李女士**:
      - **痛点**: 难以找到合适的、难度适中的练习题资源。自己出题不专业。
      - **需求**: 获取现成的、高质量的练习题，并能方便地打印出来给孩子做。
  - **3.1.4 动机与目标**
    - **王老师**: 提高教学效率，让学生有标准化的练习材料。
    - **李女士**: 辅导孩子功课，提升孩子的计算能力。
- **3.2 用户场景分析**
  - **3.2.1 核心使用场景详述**
    - **场景**: 王老师需要为班级里的40个学生布置20道竖式除法练习题作为周末作业。
    - **步骤**:
      1. 王老师打开“竖式计算练习页生成器”的网址。
      2. 页面自动从 `陈凌睿作业.json` 文件加载题目。
      3. 页面上直接展示了A4大小的预览，上面整齐排列着4x5共20道竖式计算题的框架。
      4. 王老师点击页面上的“打印”按钮。
      5. 浏览器弹出打印预览窗口，王老师确认设置后，打印出40份练习卷。
      6. 整个过程耗时不到5分钟。
  - **3.2.2 边缘使用场景考量**
    - 用户可能希望一次性生成多页（例如超过20题）。
    - 用户可能希望自定义题目的来源。

## 4. 市场与竞品分析

- **4.1 市场规模与增长预测**
  - K12在线教育市场巨大，作业辅导是其中重要一环。针对特定题型（如竖式计算）的工具市场虽小但需求刚性。
- **4.2 行业趋势分析**
  - “双减”政策下，校内提质增效和个性化学习需求增加，对高效的教学辅助工具需求上升。
- **4.3 竞争格局分析**
  - **4.3.1 直接竞争对手详析**
    - **各类“出题神器”App/小程序**:
      - **优势**: 功能丰富，支持多种题型，可拍照搜题。
      - **劣势**: 操作相对复杂，打印功能不一定友好，可能有广告或付费墙。
    - **Word/WPS模板**:
      - **优势**: 灵活性高。
      - **劣势**: 需要用户手动编辑，效率低下，门槛较高。
  - **4.3.2 间接竞争对手概述**
    - **在线教育平台 (如猿辅导、学而思)**: 提供完整的学习解决方案，但不够轻量，不专注于单一的出题打印功能。
- **4.4 竞品功能对比矩阵**
| 功能 | 本产品 | 出题神器App | Word模板 |
| :--- | :---: | :---: | :---: |
| 竖式计算生成 | ✅ | ✅ | ❌ (需手动) |
| A4/4x5自动排版 | ✅ | ❌ (通常不固定) | ❌ (需手动) |
| 从JSON加载题目 | ✅ | ❌ | ❌ |
| 打印优化 | ✅ | ⚠️ (不一定) | ✅ |
| 免费无广告 | ✅ | ❌ (大多有) | ✅ |
| 操作便捷性 | 非常高 | 中等 | 低 |

- **4.5 市场差异化策略**
  - **专注与极致**: 专注于“竖式计算打印页”这一个核心功能，做到极致的简洁和高效。
  - **开放与灵活**: 通过JSON文件加载题目，为有技术能力的用户提供了极大的灵活性。
  - **免费与纯粹**: 提供一个完全免费、无广告的纯粹工具，建立用户口碑。

## 5. 产品功能需求

- **5.1 功能架构与模块划分**
  ```mermaid
  graph TD
      A[竖式计算练习页生成器] --> B[数据加载模块];
      A --> C[页面渲染模块];
      A --> D[打印控制模块];

      B --> B1[读取JSON文件];
      B --> B2[解析题目数据];
      C --> C1[A4页面布局];
      C --> C2[4x5网格生成];
      C --> C3[竖式框架渲染];
      D --> D1[调用浏览器打印API];
  ```
- **5.2 核心功能详述**
  - **5.2.1 [功能模块1] 题目加载与处理**
    - **功能描述**: 作为用户，我希望页面能够自动从 `陈凌睿作业.json` 文件中读取题目数据，以便在页面上展示。
    - **用户价值**: 无需手动输入题目，实现自动化出题。
    - **功能逻辑与规则**:
      1. 页面加载时，前端通过HTTP请求获取 `陈凌睿作业.json` 文件。
      2. 解析JSON文件，得到一个包含问题和答案对象的数组。
      3. 每次生成页面时，从数组中按顺序取出20道题。如果需要生成多页，则继续向后取。
      4. 从问题字符串（如 "76 ÷ 38 ="）中解析出被除数、除数和运算符。
    - **交互要求**: 无用户交互，过程自动完成。
    - **数据需求**: `陈凌睿作业.json` 文件，格式为 `[{"problem": "...", "answer": "..."}]`。
    - **技术依赖**: 无。
    - **验收标准**:
      - 页面能够成功加载并解析 `陈凌睿作业.json` 文件。
      - 能够正确从 "76 ÷ 38 =" 中提取出被除数76和除数38。
      - 如果JSON文件加载失败，页面应给出友好提示。
  - **5.2.2 [功能模块2] 竖式计算页面生成**
    - **功能描述**: 作为用户，我希望加载的20道题目能自动在一个模拟A4纸的页面上，按照4列5行的网格格式清晰地展示出来。
    - **用户价值**: 获得一个排版工整、可供打印的练习页面。
    - **功能逻辑与规则**:
      1. 页面主体是一个固定比例的容器，模拟A4纸张（宽高比约为1:1.414）。
      2. 在该容器内，使用CSS Grid或Flexbox创建一个4x5的网格布局。
      3. 每个网格单元内，渲染一个竖式计算的框架。
      4. 竖式框架需要包含除号、被除数、除数的位置，并为商、计算过程和余数留出足够的空白空间。
      5. 题目的序号（1-20）应显示在每个竖式框架的左上角。
    - **交互要求**: 页面布局应在不同屏幕尺寸下保持A4比例，内容等比缩放。
    - **数据需求**: 解析后的20道题目数据。
    - **技术依赖**: HTML, CSS。
    - **验收标准**:
      - 页面在屏幕上呈现为一个A4比例的白板。
      - 20道题不多不少，整齐地排列成4列5行。
      - 每个题目都有一个清晰的、标准的竖式除法框架。
      - 框架内的被除数和除数位置正确。
  - **5.2.3 [功能模块3] 打印功能**
    - **功能描述**: 作为用户，我希望能有一个“打印”按钮，点击后可以方便地将当前看到的A4页面打印出来。
    - **用户价值**: 将数字内容转化为实体练习卷。
    - **功能逻辑与规则**:
      1. 页面上提供一个明显的“打印”按钮。
      2. 使用CSS媒体查询 (`@media print`) 来定义打印样式。
      3. 打印样式中，应隐藏“打印”按钮本身及其他非练习内容的UI元素。
      4. 打印样式应确保A4容器铺满打印页面，无多余边距。
      5. 点击按钮时，触发 `window.print()` JavaScript事件。
    - **交互要求**: 点击按钮后，应立即弹出系统打印对话框。
    - **数据需求**: 无。
    - **技术依赖**: JavaScript `window.print()` API, CSS `@media print`。
    - **验收标准**:
      - 点击“打印”按钮后，浏览器打印预览正常弹出。
      - 打印预览中的页面内容与网页上看到的A4区域完全一致。
      - 打印预览中不应包含“打印”按钮等无关元素。
      - 打印输出的纸张内容清晰、布局正确。
- **5.3 次要功能描述**
  - **分页功能**: 如果题库题目超过20道，可以生成下一页。
- **5.4 未来功能储备 (Backlog)**
  - 自定义题库来源（上传文件或手动输入）。
  - 支持其他运算类型（加减乘）。
  - 生成答案页。
  - 题目乱序功能。

## 6. 用户流程与交互设计指导

- **6.1 核心用户旅程地图**
  ```mermaid
  journey
      title 教师打印练习卷
      section 准备
        进入网站: 教师打开浏览器, 输入URL
      section 生成
        自动加载: 页面自动加载题目并排版
        预览页面: 教师检查页面布局和题目
      section 打印
        点击打印: 教师点击“打印”按钮
        确认打印: 在系统打印对话框中确认
      section 完成
        获取纸质版: 从打印机取出练习卷
  ```
- **6.2 关键流程详述与状态转换图**
  - **页面加载流程**
    ```mermaid
    stateDiagram-v2
        [*] --> 加载中
        加载中 --> 加载成功: 成功获取并解析JSON
        加载中 --> 加载失败: 网络错误或JSON格式错误
        加载成功 --> 渲染页面
        渲染页面 --> 准备就绪
        加载失败 --> 显示错误提示
        显示错误提示 --> [*]
        准备就绪 --> [*]
    ```
- **6.3 对设计师 (UI/UX Agent) 的界面原型参考说明和要求**
  - **核心要求**: 极简主义。页面除了A4画板和打印按钮外，不应有任何多余元素。
  - **A4画板**: 白色背景，带有轻微的阴影效果，使其看起来像一张浮在页面上的纸。
  - **网格**: 网格线不可见，通过间距（`gap`）来分隔题目。
  - **竖式框架**: 使用`div`和边框（`border`）来构建。除号（厂字头）可以用CSS绘制或SVG图标。字体应为清晰的无衬线体或楷体，方便学生辨认。
  - **打印按钮**: 放置在页面右上角或一个固定的页头/页脚，滚动时不消失。图标建议使用打印机图标。
- **6.4 交互设计规范与原则建议**
  - **直接反馈**: 用户的所有操作（主要是打印）应立即产生反馈。
  - **零学习成本**: 功能单一，用户打开页面即知道如何使用。

## 7. 非功能需求

- **7.1 性能需求**
  - **响应时间**: 页面加载和题目渲染时间应在2秒以内。
- **7.2 安全需求**
  - 本产品为纯前端应用，不涉及用户数据提交和存储，安全风险低。仅需确保JSON文件可被正常访问。
- **7.3 可用性与可访问性标准**
  - 页面在主流浏览器（Chrome, Firefox, Edge, Safari）的最新版本上应表现一致。
  - 打印功能应能被键盘访问（Tab键切换到按钮，回车键触发）。
- **7.4 合规性要求**
  - 无特殊合规性要求。
- **7.5 数据统计与分析需求**
  - （可选）可以加入简单的页面访问量（PV）统计。

## 8. 技术架构考量

- **8.1 技术栈建议**
  - **前端**: HTML5, CSS3, Vanilla JavaScript。无需任何框架，保持轻量。
- **8.2 系统集成需求**
  - 无。
- **8.3 技术依赖与约束**
  - 依赖浏览器提供JavaScript执行环境和打印功能。
  - `陈凌睿作业.json` 文件必须与网页部署在同一域名下或允许跨域访问。
- **8.4 数据模型建议**
  - **ProblemSet**: `[{problem: string, answer: string}]`
  - **Problem**: `{dividend: number, divisor: number}`

## 10. 产品成功指标

- **10.1 关键绩效指标 (KPIs)**
  - **页面生成次数**: 用户访问并成功生成练习页的次数。
  - **打印次数**: 用户点击“打印”按钮的次数。
- **10.2 北极星指标定义与选择依据**
  - **北极星指标**: **成功打印的练习页数量**。
  - **依据**: 该指标直接反映了用户是否完成了产品的核心价值流程（从生成到获得实体练习卷），代表了产品的最终成功交付。
- **10.3 指标监测计划**
  - 通过在前端代码中对“打印”按钮的点击事件进行埋点来收集数据。
  - 每月回顾一次数据，分析用户使用情况。
